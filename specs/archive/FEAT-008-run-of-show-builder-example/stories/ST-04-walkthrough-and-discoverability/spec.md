## Functional

### User story
As a docs reader, I want the run-of-show builder page to explain itself below the live form (the "order changes the clock" framing, a metadata-tree walkthrough, and links to the related examples) and to be discoverable from the examples index and sidebar, so that I can learn the pattern the page demonstrates and find the page in the first place.

### Acceptance criteria

1. Given the page's top (`#intro`), When it loads, Then it shows the title "Run of Show Builder", two paragraphs establishing that the planner edits durations, not times, and the page computes every row's clock live, with the amplified-music curfew making order causally decisive, a `tip` callout stating every section is rendered from one metadata tree plus one template and that clock times are computed, never entered, and a `warning` callout stating "Reordering is UI-level, not XSD" that also frames this page's relationship to `/examples/choices` and the Inbox Rules Builder page.
2. Given the body copy near the live form, When read, Then it restates plainly that venue-close overflow is a duration total, not an order effect, and that reordering alone can never fix or break it.
3. Given the `#metadata-walkthrough` section, When rendered, Then it shows `<<<` region-excerpt code blocks against ST-01/ST-02/ST-03's source files (`RunOfShowExample.vue`, `RunOfShowTemplate.vue`, `RunOfShowTimeline.vue`, `RunOfShowRow.vue`, `runOfShowMath.ts`, `RunOfShowSummary.vue`), a "What It Demonstrates" list, a "How It Works" narrative, and a "Related Source" list, matching the structure of `/examples/checkout` and `/examples/advanced`.
4. Given the page's body, When read, Then it contains one-sentence mutual cross-links framed as equals with distinct angles (per the feature's decided Open question 5): a link to `/examples/choices` (the generic repeatable-ordered-choice mechanics this page specializes), a link to `/examples/checkout`'s split-payment section (the other demonstration of the running-cascade pattern), and a link to the Inbox Rules Builder page, described as "order decides which rule fires," contrasted with this page's "order decides the clock and whether it is valid."
5. Given `/examples/choices.md` and the Inbox Rules Builder page (`docs/examples/inbox-rules.md`, FEAT-006), When updated, Then each gains exactly one new sentence linking forward to this page, with no other change to either page or its components.
6. Given `docs/examples/index.md`'s "Available Demos" list and `docs/.vitepress/config.ts`'s `/examples/` sidebar, When updated, Then the new page appears at slug `/examples/run-of-show`, titled "Run of Show Builder," positioned directly after the Inbox Rules Builder entry and before "Client Onboarding Wizard" (per the feature's decided Open question 1).
7. Given the walkthrough's worked example, When read, Then it names the exact item and direction of the single documented move that clears the default program's curfew breach, matching ST-02's shipped default data and the design's resolved finding 3.
