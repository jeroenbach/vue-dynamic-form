## Functional

### User story
As a docs reader, I want the workout plan builder page to explain itself (why order matters, where the coaching conventions come from, a metadata-tree walkthrough, and links to the related examples) and to be discoverable from the examples index and sidebar, so that I can learn the technique the page demonstrates and find the page in the first place.

### Acceptance criteria

1. Given the page's top, When it loads, Then `#page-intro` shows the title "Workout Plan Builder", a lede establishing that a workout is an order, not just a bag of exercises ("the order is the plan"), the one-metadata-tree-plus-one-template reveal, an `info` callout sourcing the coaching conventions (citing published sources, the way the checkout cites Baymard/Shopify), and a `warning` callout stating plainly this is not training advice and that nothing built here is saved anywhere.
2. Given the five rules listed in `#violations`, When rendered, Then the page shows the static prose description of each rule (warm-up first, cooldown last, compound before isolation, no back-to-back same muscle group, no adjacent high-intensity cardio) and a `warning` callout naming pre-exhaustion training as a deliberate, published exception to the compound-before-isolation rule, with the same candour the checkout uses for its "ordering is UI-level, not XSD" caveat. This prose is static; the live, data-driven violation display (the rail section and the row badges) is ST-03's and is not touched here.
3. Given the `#metadata-walkthrough` section, When rendered, Then it shows `<<<` region-excerpt code blocks against the ST-01/ST-02/ST-03 source files (`WorkoutPlanExample.vue`, `WorkoutPlanTemplate.vue`, `WorkoutBlockRow.vue`, `workoutPlanMath.ts`), a "What It Demonstrates" list, a "How It Works" narrative, and a "Related Source" list naming all five page-local files including `WorkoutPlanSummary.vue` (link only, no excerpt; see the DECIDED note in the Architecture reference), matching the structure of `/examples/checkout` (the complete structural model; `/examples/advanced` is a lighter precedent without "How It Works" or the `aside: false` nav list).
4. Given the page's body, When read, Then it contains a one-directional cross-link to `/examples/choices` (the generic mechanics this page specializes) and to `/examples/checkout`'s split-payment section (the other existing demonstration of the shape), each with a sentence explaining why this page exists as the dedicated showcase. If FEAT-008's page has already shipped by the time this story implements, a third one-directional cross-link to it is added per the feature's DECIDED Open question 6; if not, this bullet is satisfied by the two links above and the FEAT-008 link becomes a follow-up amendment once that page exists, not a gap in this story.
5. Given the page's disclaimers, When read, Then the body copy near `#live-form` restates plainly that the page saves nothing anywhere (no account, no storage, no history) and that the ordering rules reflect common convention, not personalized or medical advice, distinct from the `#page-intro` callout.
6. Given `docs/examples/index.md`'s "Available Demos" list and `docs/.vitepress/config.ts`'s `/examples/` sidebar, When updated, Then the new page appears at slug `/examples/workout-plan`, titled "Workout Plan Builder", positioned between "Checkout" and "Client Onboarding Wizard" (per the feature's DECIDED Open question 1).
