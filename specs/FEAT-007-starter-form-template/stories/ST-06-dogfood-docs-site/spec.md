## QA plan

`docs/` has no automated test harness at all: it is explicitly excluded from the pnpm workspace (`pnpm-workspace.yaml` lists `!docs`), `docs/package.json` has only `dev`/`build`/`preview` scripts, there is no vitest config, no `@vue/test-utils` dependency, and no `__tests__` convention anywhere under `docs/`. This is unlike every other story in this feature, which ports into `packages/starter` and gets the full `*.test.ts`/`*.logic.test.ts`/`*.analytics.test.ts` treatment. Concretely this means:

- `pnpm -r ci:test:coverage` never touches `docs/`, so this story cannot move the coverage baseline in either direction. Not a gap to close, just a fact to record.
- `pnpm run ci:lint` / `pnpm run ci:typecheck` (both `pnpm -r ...`) never touch `docs/` either, for the same workspace-exclusion reason, and `docs/package.json` has no `lint`/`typecheck` script of its own to run manually in their place. AC10 as written claims these commands "pass for `docs/`," which is not literally true today regardless of what this story changes. See the rewrite proposal below.
- `pnpm docs:build` (plain `vitepress build`) is the one real automated gate this story has. It resolves actual imports against the real published package shape, so it will fail on a renamed/missing export (catches most of AC2/AC5/AC6 by construction) and on a broken stylesheet path (AC4). It does not run a type-checker (Vite/esbuild strips types without checking them), so a type-level contract mismatch (e.g. a wrong prop shape handed to `StarterFormTemplate`) would not fail the build.

Given this, the plan below proposes one new lightweight, dependency-free verification script as the closest thing to an automated test this slice can get, and is explicit about what stays manual.

### Fixtures and test utilities

- Reused: `pnpm docs:build` (existing script, no change needed) as the primary automated gate.
- New (proposed): `docs/scripts/verifyDogfood.mjs`, a plain Node script using only `fs`/`path`/regex (no test runner, no new dependency), with a matching `docs/package.json` script `"verify:dogfood": "node scripts/verifyDogfood.mjs"` (per CLAUDE.md's "every user-runnable script gets a package.json script" rule). It performs the source-scan checks the AC-to-test map below assigns it: deleted-file-list absence, kept-file presence, `iconName` migration completeness, stylesheet-import count, and Tailwind-utility-token absence in the three migrated files (same utility-pattern regex set `packages/starter`'s `noTailwind.test.ts` uses, copied as a literal array since `docs/` cannot import a sibling package's test helper across the workspace boundary).
- Not wired into CI: `.github/workflows/quality-assurance.yml` has no `docs/` job and nothing in it calls `pnpm --prefix docs run ...`. Run `verify:dogfood` locally before pushing, same as `pnpm docs:build`. Flagging whether to add a CI step for either command is an infrastructure decision beyond this story's scope; routed to adversarial-review rather than added silently.
- No `packages/core/src/examples/` fixture applies here; this story has no metadata fixtures of its own, it only rewires existing demo-page metadata.
