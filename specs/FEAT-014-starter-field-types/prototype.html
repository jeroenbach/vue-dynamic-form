Starter field types

New leaf controls for @bach.software/vue-dynamic-form-starter. Every control lives inside the same FormField chrome the existing text, select, checkbox and password fields already get: label, optional/required tag, description, and one error line below the control. The running example is a job application form.

How to read this: three new rendered components (Textarea, RadioGroup, FileInput) each get the full state matrix below. The HTML5 text-mode types at the bottom add no component, they only reach the existing TextInput through a native type attribute. Use the top-right button to flip .dark on <html>, exactly as VitePress does; every section was walked in both modes. Cells marked focus (simulated) paint the real :focus ring on a resting element so it shows in this stacked view.

Textarea

new component · slot textarea-input

Multi-line free text. Shares the input chrome tokens (border, focus ring, invalid, disabled) but grows vertically from a min-height and offers a resize handle. Chrome, validation and grid placement come from FormField unchanged.

Radio group

new component · slot radio-input

A different rendering of the same flat options: {`{ key, value }[]`} that select already uses: "which one value does this field hold". It is a sibling of select, not the structural choice (those are indigo branch cards that each own their own sub-fields). To keep the two distinct, the radio uses the sky accent, a smaller dot, and no icons or per-option descriptions. Rows are full-width tap targets analogous to the switch and select chrome.

Empty (no selection)

No dot filled. Hover a row to preview its sky border (try it).

Selected

Selected row carries is-selected: sky border + filled dot. The option's key becomes the field value.

Focus (simulated)

Keyboard focus rings the radio circle (:focus-visible on the real input). Arrow keys move within the group natively.

Invalid (with message)
Choose how you heard about us.

Resting radio circles pick up the danger border; one sft-error line below the whole group (not per option).

Disabled

Field dims to 60%, rows become not-allowed, a pre-selected value still reads.

File input

new component · slot file-input · uncontrolled

The one uncontrolled control in the package. A native <input type="file"> cannot be given a :value, so the native element is visually hidden behind a labelled trigger button and the chosen filename is shown from the component's own local state (the File read off the change event), not echoed from the form model the way every other control echoes fieldContext.value. v1 is single-file (File | undefined); multi-file, drag-and-drop and previews are out of scope (see Open question 3).

HTML5 text-mode types

type-only · existing TextInput + default-input

No new component and no new slot. These add entries to StarterValueTypes only; the existing TextInput already forwards fieldMetadata.type to the native type attribute, so the browser supplies the right affordance and keyboard. They inherit the exact FormField chrome shown above, so this section just confirms the native control renders inside that wrapper. The number type keeps the raw-string coercion guard: the model stays a string, validated by xsd_minInclusive/xsd_maxInclusive/xsd_totalDigits.

number

Native spinner; value stays a string in the model.

email

Email keyboard on mobile; xsd_pattern still owns explicit validation.

tel

Numeric-telephone keyboard on mobile.

URL keyboard on mobile.

date

Native date picker; value is the browser's ISO string, parsing left to the consumer.

Native time picker.

Native combined date and time picker.

invalid + disabled
Enter a valid email address, like you@company.com.

Same invalid/disabled treatment as the text type: no new states, only new keyboards.
